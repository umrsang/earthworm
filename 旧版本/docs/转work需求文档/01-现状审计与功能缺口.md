# Earthworm 现状审计与功能缺口

## 1. 审计结论

Earthworm 已具备可用的核心骨架：账号密码登录、课程包三级数据结构、课程学习、两种答题模式、进度保存、学习时长、掌握列表、排行榜、课程包上传及部分管理能力。前端现有 30 个单测文件共 213 个用例通过，说明底层学习逻辑相对稳定。

但目前仍不适合把历史路线图中的“v1.1 已完成”直接视为产品完成。主要原因是：

- 多处按钮有视觉入口但没有业务结果，例如会员升级按钮为空实现。
- 有接口但没有完整页面闭环，例如会员购买仅有后端写入，没有商品、支付、订单和结果处理。
- 有主状态但缺少加载、空、错误、无权限、离线、删除恢复等状态。
- 课程管理仅覆盖课程包和课程，语句管理在用户可见界面中没有形成完整编辑流。
- 上传课程包默认写为 `public`，与历史说明中的“默认私有”矛盾，存在误公开风险。
- 首页学习日历年份固定，切换逻辑未实现。
- 移动端和键盘用户难以发现课程卡片的编辑、删除操作。
- 历史路线图把夜间模式、快捷键、排行榜等仍标为“计划”，但代码已经具备相关能力，文档已经失真。

因此建议先发布 v1.5「体验补全版」，再进入 v2.0。

### 2.1 已检查范围

- Nuxt 页面路由、全局布局、导航、用户菜单。
- 课程包列表、详情、上传、学习、结算、掌握列表、设置。
- NestJS Controller、Service 与数据库 Schema。
- 现有 UI 设计变量及交接说明。
- 当前 Git 工作区中的在制修改。
- 前端单元测试和类型检查可执行性。

### 2.2 质量检查结果

| 检查项     | 结果     | 说明                                                                       |
| ---------- | -------- | -------------------------------------------------------------------------- |
| 前端单测   | 通过     | 30 个测试文件、213 个用例通过                                              |
| Vue 警告   | 有风险   | 分享图、彩蛋测试中出现 `onMounted` 无活动组件实例警告                      |

## 5. 明确的不完整功能清单

### P0：必须在下一次正式发布前解决

1. 课程包上传的默认可见性改为私有，或在提交前要求用户显式选择并二次确认公开。
2. 会员升级按钮在未接真实交易前改为“加入候补/了解权益”，禁止产生支付成功暗示。
3. 掌握列表删除增加确认、loading、失败恢复。
4. 课程包/课程管理操作在移动端、键盘焦点和触屏上始终可发现。
5. 补齐语句添加、编辑、删除、排序的管理闭环，或从文案中移除“完整 CRUD”承诺。
6. 学习日历年份按查询参数真正生效。
7. 统一课程权限枚举和前后端类型，防止未知字符串写入。
8. ZIP 解析增加大小、条数、字段 Schema、安全限制与错误定位。
9. 登录拦截保存来源路由，登录成功返回原目标页。

### P1：v1.5 应完成

1. 所有核心页面覆盖 loading、empty、error、no-permission、offline 五类状态。
2. 课程包增加搜索、来源/权限筛选、排序和我的课程区分。
3. 学习页统一错误反馈、触屏操作、快捷键提示和离开保护。
4. 首页增加今日目标、连续学习、待复习、正确率四个关键指标。
5. 设置增加自动保存提示、恢复默认和跨设备同步说明。
6. 结算页增加正确率、错题数、掌握数和明确的下一步建议。
7. 课程包上传改为三步向导：选择文件 → 校验与编辑 → 发布确认。
8. 增加关键业务 E2E：注册、登录回跳、开始学习、完成、上传、删除、设置保存。

### P2：可放入 v2.0

1. 勋章与成就。
2. 课程市场、收藏和评价。
3. 错题本与间隔重复。
4. 每日学习计划和提醒。
5. 课程版本、导出和复制。

## 6. 现有功能的非功能风险

### 6.1 可访问性

- 图标按钮需要可见 `aria-label`，不能只依赖 Tooltip。
- 所有按钮、卡片、抽屉菜单必须可通过 Tab 到达。
- 焦点样式不可被 `focus:outline-none` 单独移除。
- 颜色状态必须同时有图标或文字。
- 最小点击区域 44×44px。

### 6.2 数据与权限

- 公开课程包必须记录发布人、发布时间和最近编辑时间。
- 删除课程包应检查关联学习记录，产品需选择“软删除并保留用户进度快照”或“明确永久删除”。
- 会员购买接口不能接受客户端传入任意 `userId` 后直接生效，应从认证上下文获取用户。
- 上传与更新接口需限制用户输入长度、URL 协议和 JSON 体积。

### 6.3 性能

- 大 ZIP 解析放到 Web Worker，UI 每 200ms 更新一次进度。
- 课程包列表采用分页或游标，图片懒加载。
- 课程目录超过 300 条时使用虚拟列表。
- 排行榜缓存要有明确 TTL 和错误失效策略。

### 6.4 可观测性

至少记录：

- 登录/注册成功率与失败原因。
- 课程包曝光、打开、开始学习、完成。
- 每道题首次正确率、提示使用、跳过、掌握。
- 上传解析失败原因和发布成功率。
- 设置变更、主题变更、快捷键冲突。
- 错误页重试成功率。

## 7. 结论与实施边界

v1.5 的目标不是增加更多菜单，而是消除当前所有“看得见但做不完”的路径。只有满足以下条件才进入 v2.0：

- P0 全部关闭。
- 核心页面状态覆盖达到 100%。
- 注册到完成第一课 E2E 通过。
- 上传课程包不会默认误公开。
- 会员入口不存在空按钮或虚假交易结果。
- 设计稿、产品文档、接口契约、代码文案一致。
