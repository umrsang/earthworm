# Earthworm 原型配套后端开发计划

> 目标：以当前原型为接口验收基线，先补齐真实数据闭环，再接入页面。所有学习结果必须由后端记录和计算，不能继续依赖原型静态数字或 localStorage。

## 一、交付顺序

### P0：阻塞主流程与数据安全

1. 课程包上传默认保存为 `private + draft`，只有显式发布才允许公开。
2. 上传 DTO 对课程、语句和嵌套字段做服务端校验；单包最多 100 课、单课最多 2000 句。
3. 上传时使用明确的课程包 ID，禁止通过“创建者 + 同名标题”反查。
4. `GET /user` 返回 id、username、avatar、email、会员信息。
5. 记录每次作答：答案、正确与否、是否使用提示、耗时、课程与语句来源。
6. 错误作答自动进入复习队列；正确作答更新掌握度和下次复习时间。

### P1：原型核心页面

1. 今日计划：按日期读取和覆盖保存目标、完成数及任务项。
2. 课程库：加入学习、收藏/取消收藏、读取“我的课程”。
3. 复习中心：到期、错题、全部三类列表；提交复习结果；延后复习。
4. 创作者：新建空白课程包、新增课程、新增语句；保留已有修改和删除。
5. 课程包元数据：草稿/已发布、难度、标签、可见范围。

### P2：设置、通知、学习洞察

1. 设置：读取、合并更新、恢复默认；登录设备共享。
2. 通知：列表、创建、单条已读、全部已读。
3. 洞察：作答量、正确率、首次正确率、完成语句数、学习时长、薄弱语句。
4. CSV 导出先提供作答明细文件响应，后续增加异步大文件任务和日期范围限制。

## 三、数据表

- `learning_attempts`：不可变作答事实表，是正确率、错题和洞察的唯一来源。
- `review_items`：每个用户每条语句一条调度状态，记录掌握度、错误次数、间隔和到期时间。
- `daily_plans`：每个用户每天一条计划。
- `user_course_library`：用户和课程包关系，含加入时间、收藏状态。
- `user_preferences`：用户设置 JSON；新增字段不需要频繁改表。
- `notifications`：站内通知及已读时间。
- `course_packs` 新增 `difficulty`、`tags`、`status`。

## 四、开发验收

1. `pnpm schema:build` 和 `pnpm -F api build` 必须通过。
2. 新增接口必须出现在 Swagger，除登录注册和公开课程外均要求 JWT。
3. 两个同名课程包连续上传必须返回不同且正确的 ID。
4. 上传未传可见性时必须为私有草稿。
5. 错误作答后立刻可在 `review?type=wrong` 查询；复习正确后到期时间向后移动。
6. 设置在重新登录后仍可读取；恢复默认后返回完整默认配置。
7. 用户 A 无法读取或修改用户 B 的计划、复习、收藏、设置和通知。
